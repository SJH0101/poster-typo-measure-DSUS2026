판정 조건을 말로 적으면:

- 짝 후보: `|ŷ − y| ≤ 0.5·ℓ` **그리고** 가로 겹침 `min(t.x2, p.x2) − max(t.x1, p.x1) > 0`.
- 짝짓기 순서: `|ŷ − y|` **작은 순서**로 1:1 탐욕 (`sorted(...)` 는 오름차순).
- 맞음(`hit`): `|e| ≤ 0.2·ℓ`, `e = ŷ − y`.
- 재현율 = `허용안_짝 / 참값_선`, 정밀도 = `허용안_짝 / 측정_선`, F1 = `2·허용안_짝 / (참값_선 + 측정_선)`.
- 따로 두는 값: `창안_짝` (창 안에서 짝지은 수, 허용 밖도 포함) 과 `창안짝_정밀도 = 창안_짝 / 측정_선`.
- 오차 중앙 = **창 안 짝** 의 `|e|` 중앙값 (허용 안 짝만이 아니다).
- ℓ 은 블록마다: 베이스라인 2개 이상이면 그 차의 중앙값, 아니면 `2 × median(base − xh)`, 아니면 판 중앙값.
- 측정 선에서 빼는 것 (`line_score:485–488`): 측정 블록이 제외 사유 블록 안에 `inside ≥ 0.5` 이면 뺀다(`ex_f`),
  그 다음 글줄 판독 불가 블록 안에 `inside ≥ 0.5` 이면 뺀다(`ex_i`). 남은 블록(`live`)의 선만 `측정_선` 에 든다.
- ③(두 라벨러 일치 항목) 은 정밀 분모를 더 줄인다 — `정밀분모에서_뺀_측정선` (`:996`), 짝 후보 조건도 두 라벨러 값 모두에 대해 본다 (사전등록 수정 1 «③ 의 채점 정의 · 선»).

판정 조건을 말로 적으면:

- 짝짓기 전에 **측정 묶음을 뺀다**: 제외 사유 블록 `x` 에 대해 `inside(묶음, x) ≥ 0.5` 이면 뺀다 (`제외로_뺀_묶음`).
- 짝 후보: `IoU ≥ t` (주 0.5, 민감도 0.3), **IoU 큰 순서**로 1:1 탐욕.
- 재현 = `짝 / 참조`, 정밀 = `짝 / 묶음`(뺀 뒤 수), F1 = `2·짝 / (참조 + 묶음)`.
- 판마다 센 값을 `Counter` 로 합산한 뒤 F1 을 낸다 (판별 F1 의 평균이 아니다).
- 과병합: 한 묶음이 **서로 다른 참조 둘 이상**을 각각 `held ≥ 0.5` (참조 넓이 기준) 로 덮은 경우의 **묶음 수**.
- 과분할: **짝 못 지은** 묶음 가운데 **어떤 한 참조** 안에 `inside ≥ 0.5` (묶음 넓이 기준) 로 든 **묶음 수**.
- 헛것: 어느 참조와도 겹치지 않는 묶음 수.
- ③ 은 두 라벨러 상자에 대해 `min(IoU)` · `min(held)` · `min(inside)` 를 쓰고 제외 범위도 더 넓다 (`block_counts_agreed`).

## 2. 1절의 (c) 와 `docs/brockmann_stage2_result.json` 이 같은가

| 항목 | 1절 (c) · 합의 | `brockmann_stage2_result.json` 합의 베이스라인 | 같은가 |

| 측정 선 | 903 | 901 | **다르다** |
| 창 안 짝 | 829 | 829 | 같다 |

**원인.** 짝과 맞음은 같다 (창 안 짝 829 · 허용 안 짝 823). 다른 것은 `측정_선` 분모뿐이다 — 903 대 901.
두 경로가 측정 선을 거르는 단위가 다르다:

- `brockmann_stage2_score.line_score:485–488` — **측정 블록 단위**로 뺀다. 블록이 제외 사유 블록 안에
  `inside ≥ 0.5` 이면 그 블록의 선 전부를 빼고(`ex_f`), 글줄 판독 불가 블록에 대해 한 번 더 뺀다(`ex_i`).
- `eval/explore_vlm_baseline.keep:156–157` — **선 하나 단위**로 뺀다. 선의 가로 중점이 제외 영역의
  가로 범위 안이고 y 가 그 영역 안일 때만 뺀다.

그래서 같은 캐시 · 같은 참조인데도 측정 선이 2개 더 남아 정밀도가 0.9114 대 0.9134 로 갈린다.
재현율은 분모가 참값 선(921)이라 완전히 같다.

### 2.1 짝지은 줄 수와 미검출 수

**맞지 않는다 — 다른 함수의 수다.** 미검출 93 은 `eval/explore_split_lines.missed_causes:89–129` 가 낸 값이고,
1절·stage2 의 선 채점(`line_score` · `_direct`)과 세 가지가 다르다:

1. **측정 선을 거르지 않는다.** `missed_causes` 는 캐시의 모든 블록 베이스라인을 후보로 쓴다
   (제외 사유 · 판독 불가 블록을 빼지 않는다, `:106`).
2. **행간 ℓ 규칙이 다르다.** 블록 안 베이스라인이 1개면 `2 × (base − xh)` 를 쓰고 그것도 없으면 `2 × 10.0` 을

3. 그래서 같은 캐시로 돌리면 짝이 828 이고 (921 − 93), `line_score` 의 허용 안 짝 823 보다 5 많다.

즉 «미검출 93» 과 «놓친 라벨 92/98» 은 **같은 수를 다르게 센 것이 아니라 정의가 다른 수**다.
논문에 둘을 나란히 쓰면 서로 맞지 않는다.

## 4. 논문에 적힌 지표 정의와 코드가 다른 곳

논문 문단(아래 «논문» 열)을 0절의 코드와 한 줄씩 맞춘 목록이다. **코드를 고치지 않았고 논문 문구도
고치지 않았다** — 다른 자리만 적는다.

### 4.1 선 채점

| # | 논문 | 코드 | 무엇이 다른가 |
|---|---|---|---|
| L1 | «두 선의 차가 0.5ℓ 이내인 쌍을 … 대응» | `_direct:468–469` 는 `|ŷ−y| ≤ 0.5·ℓ` **그리고** `min(t.x2, p.x2) − max(t.x1, p.x1) > 0` | **가로 겹침 조건이 빠졌다.** 코드는 가로로 전혀 겹치지 않는 선끼리는 짝짓지 않는다 |
| L2 | «해당 블록의 행간을 ℓ» | `block_L:202–212` — 베이스라인 2개 이상이면 그 차의 중앙값, 1개면 `2 × median(base − xh)`, 그것도 없으면 **판 전체 중앙값** | ℓ 의 세 갈래 규칙이 빠졌다. 특히 한 줄 블록과 x높이선 없는 블록에서 값이 달라진다 |
| L3 | «정밀도는 맞은 수를 \|Ŷ\|로 나눈 값» | `_stats:694` 의 분모 `n_m` 은 `line_score:485–488` 에서 **측정 블록을 빼고 남은**(`live`) 블록의 선 수 | 분모에서 빼는 규칙이 빠졌다 — 제외 사유 블록 안 `inside ≥ 0.5` 인 측정 블록(`ex_f`), 그 다음 글줄 판독 불가 블록 안 `inside ≥ 0.5` 인 블록(`ex_i`) |
| L4 | (없음) | `_stats:694` 는 `창안짝_정밀도 = 창안_짝 / 측정_선` 을 따로 낸다 | 코드에는 정밀도가 **둘**이다. 논문은 하나만 적어, 결과 파일의 `창안짝_정밀도` 와 혼동될 수 있다 |
| L5 | «오차 중앙은 \|e\|의 중앙값» | `_stats:695` 는 **창 안 짝 전부**(허용 밖 포함)의 `|e|` 중앙값 | 어느 집합의 중앙값인지가 빠졌다. «맞은 쌍의 중앙값» 으로 읽으면 다른 수가 된다 |
| L6 | (없음) | ③(두 라벨러 일치 항목) 은 짝 후보를 두 라벨러 값 **모두** 에 대해 `≤ 0.5·ℓ` 로 보고, 짝짓기 비용이 «두 차의 절댓값 가운데 큰 쪽», 허용도 두 차 모두 `≤ 0.2·ℓ`, 정밀 분모를 더 줄인다 (`정밀분모에서_뺀_측정선`, `:996`) | 논문 정의는 참조가 하나인 경우만 적어 ③ 열을 설명하지 못한다 |
| L7 | (없음) | 참조 선에서 빠지는 것: 제외 사유 블록 · `block_L` 이 `None` 인 블록의 글줄(`L_없어_뺀_글줄`, `line_score:496`) | 참조 쪽 제외 규칙이 빠졌다 |

### 4.2 블록 채점

| # | 논문 | 코드 | 무엇이 다른가 |
|---|---|---|---|
| B1 | «IoU ≥ 0.5 인 쌍을 IoU 큰 순서로 1:1 대응» | `match_t:175–185` 같음 | 같다 |

여섯 줄 모두 같다. 함수 구성상 같을 수밖에 없다 — 미검출을 «`T` 가운데 `hit` 인 짝이 없는 것» 으로 세고
허용 안 짝을 «`hit` 인 짝» 으로 세므로 둘의 합이 `len(T)` = 참값 선이다. 기존 함수에서는 `T` · `P` 를 따로
만들어 이 항등식이 성립하지 않았다.

### 12.4 왜 다른가 — 세 가지 차이가 각각 얼마를 움직였나

| 차이 | 무엇이 달라지나 | 값 (합의 · 끔 → 켬) |
|---|---|---|
| ① 측정 선 거르기 | 기존은 캐시 블록의 베이스라인을 전부 쓴다. 선 채점은 제외 사유 블록에 `inside ≥ 0.5` 인 측정 블록을 뺀다 (`line_score:485–488`) | 측정 선 876 → 862 · 915 → 901 (뺀 측정 블록 7개) |

원인 분류가 움직이는 방향도 ① 로 설명된다 — 측정 선이 14개 줄어 **«가로 병합» 후보가 줄고 (81 → 79,
50 → 48) 그만큼 «띠 없음» 이 늘어난다 (37 → 44, 36 → 43)**. 「가로 병합」은 «못 짝지은 글줄 ±1px 안에
가로로 겹치는 측정 베이스라인이 있고 그것이 다른 글줄과 짝지어졌을 때» 이므로, 그 측정 베이스라인이
거르기로 빠지면 같은 글줄이 «띠 없음» 으로 옮겨 간다.

### 12.5 곁따라 확인한 것 — 코퍼스 캐시는 지금 «가르기 켬» 상태다

위 계산 중에 확인했다 (`docs/split_only_score.json` `캐시와_같은_판`). `~/.typo-mcp/brockmann.json` (provenance `8a5b0a1` · 2026-09-20 · n 123) 의 블록은

|---|---|

코드가 움직인 것이 아니라 **캐시가 `split_lines=True` 로 다시 쟤진 것**이다. 12.1 절의 두 조건은 캐시를

### 16.3 무작위 대조 (ii) — 코드 그대로, 원고 문장과 다른 곳

코드는 (ii) 를 **두 가지**로 쓴다.

```python
# eval/explore_typography_rules2.py:149
def perm_ctrl(flat, seg, stat, trials=TRIALS):
    """(ii) 순열 — 값의 분포는 그대로, 판 배정만 뒤섞는다."""
    flat = np.asarray(flat, dtype=float)
    res = []
    for _ in range(trials):
        res.append(stat(rng.permutation(flat)))
    return ci([r for r in res if r is not None])

# eval/explore_typography_rules2.py:167
def jit_ctrl(flat, stat, amp=JIT, trials=TRIALS):
    """(ii) 흔들림 — 값마다 ±amp px 안의 흔들림을 더한다."""
    flat = np.asarray(flat, dtype=float)
    res = []
    for _ in range(trials):
        res.append(stat(flat + rng.uniform(-amp, amp, len(flat))))
    return ci([r for r in res if r is not None])
```

`flat` 은 **모든 판의 값을 한 줄로 이은 배열**이고, `seg` 는 판마다 몇 개인지다. 통계 함수(`a1` ·
`b1` · `c1` 등)가 `seg` 로 다시 잘라 판별 값을 낸다. 그래서 `rng.permutation(flat)` 은 **판마다의
개수는 그대로 두고 어느 값이 어느 판에 들어가는지를 바꾼다.**

원고 3-6 의 문장과 견주면 세 곳이 다르다.

| 원고 3-6 | 코드 | 어긋남 |
|---|---|---|
| «실제 값의 분포를 유지한 채» | `rng.permutation(flat)` — 전체 분포 그대로 | **같다** |
| «**포스터 내에서** 순서만 뒤섞어» | 판 **사이**로 값을 다시 나눠 준다 (`perm_ctrl` 독스트링 «판 배정만 뒤섞는다») | **다르다.** 표 6 의 통계는 모두 한 판 안 값들의 **집합**만 쓰므로(중앙값 · 묶음 수 · 군집 수 · 몫), 판 안에서 순서만 바꾸면 값이 **하나도 변하지 않는다** — 원고 문장대로면 대조가 실제 값과 같아져 판정이 불가능하다 |
| (한 가지 절차로 적었다) | A2 와 C4 는 순열이 아니라 **`jit_ctrl` 흔들림**이다 — A2 는 ±2px, C4 는 ±0.3 x높이배 (`:459`) | **다르다.** 표 6 의 「줄 간격이 기본 간격의 정수배인 비율」은 순열 대조가 아니다. 간격을 뒤섞으면 최소 간격 자체가 바뀌어 비가 뜻을 잃으므로 흔들림을 쓴다 |
| «같은 계산을 2,000회 반복하고» | `TRIALS = 2000` (`:23`) | 같다 |
| «95% 구간 밖에 있을 때만 규칙으로 판정» | `judge` (`:51`) · `ci` 의 2.5 ~ 97.5 백분위 (`:45`) | 같다 |

적지 않은 것 하나 — 코드는 대조를 **둘** 낸다. (i) 균등 (`unif_ctrl:158`, 값의 범위에서 균등하게
다시 뽑기)도 결과 파일에 함께 있지만 **판정에는 쓰지 않는다** (`judge` 는 `c2` 만 본다). 원고가 (i) 를

## 19. N등분 격자 분석의 무작위 대조 (ii) — 정렬 구조를 지키지 않는다

11 절의 판정은 대조 (ii) 를 기준으로 한다 (`docs/grid_ndiv_preregister.json` 결정 6 ·
`eval/grid_ndiv.py:178`). 그 (ii) 가 무엇을 유지하고 무엇을 버리는지를 적는다. **11 절의 값은
고치지 않는다** — 아래는 그 값을 읽는 조건이다.

### 19.1 대조 (ii) 가 만드는 것 — 코드 그대로

```python
# eval/grid_ndiv.py:105
def rand_posters(posters, rng, mode):
    """대조 한 벌. (i) 모서리 균등 · (ii) 블록 크기 유지하고 위치만 균등."""
    out = []
    for p in posters:
        W, H = p['W'], p['H']
        if mode == 'i':
            nb = len(p['blocks'])
            v = rng.uniform(0, H, 2 * nb); h = rng.uniform(0, W, 2 * nb)
        else:
            v, h = [], []
            for b in p['blocks']:
                w, ht = b['x2'] - b['x1'], b['y2'] - b['y1']
                x1 = float(np.floor(rng.uniform(0, max(W - w, 0) + 1e-9)))
                y1 = float(np.floor(rng.uniform(0, max(H - ht, 0) + 1e-9)))
                v += [y1, y1 + ht]; h += [x1, x1 + w]
```

사전등록도 같은 말이다 — «블록의 폭 · 높이를 그대로 두고 판 안에 들어가도록 왼쪽 위 좌표를
균등하게 다시 뽑는다 (x1 ~ U[0, W − w], y1 ~ U[0, H − h], 정수로 내림)» (결정 6).
`grid_ndiv.py` 에 흔들림(jitter)도 순열(permutation)도 없다 — `rng.uniform` 세 곳이 전부다.

| | (ii) 에서 |
|---|---|
| 판 크기 · 판별 블록 수 · 모서리 개수 (2 × 블록 수) | **유지** |
| 블록마다의 폭 · 높이 (한 블록의 두 x모서리 간격 = w, 두 y모서리 간격 = h) | **유지** |
| 블록끼리의 자리 관계 — 왼쪽 끝 공유(정렬) · 단 구조 · 위아래 쌓임 · 블록 사이 간격 | **유지하지 않는다** (블록마다 독립 추출) |

즉 (ii) 는 «실제 배치를 흔들거나 옮긴 것» 이 아니라 **블록 크기만 붙여서 판 위에 고르게 다시
뿌린 것**이다. 사전등록이 (ii) 를 «구조만 흔들기» 로 부른 것은 **크기 구조**를 뜻하고 배치 구조가
아니다. (i) 과의 차이는 «네 모서리를 따로 뽑는가 / 블록 단위로 크기를 붙여 뽑는가» 뿐이다.

### 19.2 그래서 11.2 의 «최적 N 우연 이상» 을 어떻게 읽나

실제 판의 모서리는 정렬 때문에 **같은 x 값에 겹쳐 모인다.** 16.2 의 왼쪽 정렬 위치 수가 그 크기다 —
브로크만은 판당 **3.72** 인데 같은 계열의 대조는 **6.30–6.60** 이다. 실제 판의 서로 다른 왼쪽 끝
자리가 대조의 약 **절반**이라는 뜻이다.

모서리가 적은 수의 자리에 몰려 있으면 **어떤 N 이든 그 자리들을 한꺼번에 맞히기 쉬워져** 판마다
고른 최적 N 의 일치율이 올라간다. (ii) 는 그 몰림을 풀어 버린다. 그러므로 11.2 의
«최적 N 일치율이 대조 구간 밖 (측정 0.600 대 0.550–0.563)» 은 **«N등분 격자가 있다» 는 증거로
읽을 수 없다 — «모서리가 되풀이된다(정렬이 있다)» 는 사실만으로도 나올 수 있는 결과다.**

11.2 의 다른 값은 이 문제에 걸리지 않는다. «어느 N 도 두 자리 이상 연이어 구간을 벗어나지
않는다» 는 고정된 N 에 대한 진술이고, 거기서는 실제와 대조가 같은 모서리 개수를 쓴다.

| 11 절의 값 | 이 문제에 걸리나 |
|---|---|
| N 별 합침 일치율 (표 7 의 네 칸 · 범위 0.274~0.365) | 걸리지 않는다 — 실제 값 자체이고 대조를 쓰지 않는다 |
| «두 N 이상 연이어 구간 밖인 경우 없음» | 걸리지 않는다 |
| **«최적 N 일치율이 대조보다 높다 → 우연 이상»** | **걸린다** — 정렬 몰림만으로도 설명된다 |
| 신실라 환산값 (11.3) | 걸리지 않는다 — 대조를 쓰지 않는다 |

### 19.3 사전등록에 적혀 있던 것과 없던 것

`docs/grid_ndiv_preregister.json` `한계 (미리)` 가 (ii) 에 대해 적은 것은 하나다 —
«무작위 (ii) 는 블록 크기를 유지하지만 블록끼리 겹칠 수 있다 — 실제 판에는 없는 배치가 섞인다».
**정렬 몰림을 지키지 않는다는 점은 적혀 있지 않다.**

사전등록 `결과를 보고 바꾸지 않는 것` 에 «무작위 두 방식과 시행 2,000» 이 들어 있으므로,
세 번째 대조를 그 분석에 더하면 결과를 본 뒤의 변경이 된다. 그래서 고치지 않고, 정렬 구조를
유지한 대조는 **새 사전등록(`docs/grid_module_preregister.json`, 단독 커밋 `ac6dec3`)으로 분리해**
18 절에 따로 냈다. 18 절의 대조는 정렬 위치의 **개수를 유지**하고 위치만 다시 뽑는다.
